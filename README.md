# Эмулятор оболочки — вариант 11

Практическая работа по дисциплине «Конфигурационное управление».
Реализация на Kotlin/JVM с графическим интерфейсом Swing для macOS.

## Текущий этап

Выполнены этапы 1–5 варианта 11: графический REPL, конфигурация,
виртуальная файловая система из ZIP, основные команды и смена владельца VFS.
Этап 4 находится в ветке `codex/stage-4`, этап 5 — в `codex/stage-5` поверх этапа 4.
Каждый из этих этапов сохранён отдельным коммитом.
Заголовок окна содержит имя выбранной VFS.

## Требования к запуску

- JDK 21.
- Gradle 8.13 (Kotlin 2.2.21 загружается средствами Gradle).
- При первой сборке нужен доступ к репозиториям зависимостей.

`scripts/gradle.sh` использует `GRADLE_BIN`, установленный `gradle` или Gradle 8.13
из стандартного кеша Gradle. Если ничего не найдено, скрипт сообщает об этом.
Бинарный Gradle Wrapper не включён: задание запрещает бинарные файлы в репозитории.

## Сборка, тесты и запуск

```sh
./scripts/gradle.sh clean test installDist
./scripts/gradle.sh guiTest
./run.sh
```

Если Gradle не находится автоматически:

```sh
export GRADLE_BIN=/путь/к/gradle-8.13/bin/gradle
./run.sh
```

`run.sh` собирает приложение и открывает окно. Скрипт запуска можно вызывать
из любого каталога. Исходники находятся в `src/main/kotlin`, тесты — в `tests`.
Результаты сборки и зависимости не добавляются в Git.

`test` работает без графического экрана. `guiTest` проверяет настоящие окна Swing
и требует графической сессии macOS. Отчёты: `build/reports/tests/test/index.html`
и `build/reports/tests/guiTest/index.html`. GUI-тест сохраняет изображение панели
в `build/preview/terminal.png`.

## Команды

| Команда | Поведение |
| --- | --- |
| `ls [-alhR] [путь...]` | Перечисляет файлы и каталоги VFS. |
| `cd [путь]` | Меняет виртуальный каталог; без пути возвращает в `/`. |
| `echo [текст...]` | Выводит аргументы, соединённые пробелом. |
| `find [путь...] [-name шаблон] [-type f/d] [-print]` | Рекурсивный поиск в VFS. |
| `chown [-R] owner[:group] путь...` | Меняет владельца и/или группу только в памяти VFS. |
| `exit` | Закрывает окно и завершает приложение. Аргументы не допускаются. |
| `vfs-init` | Сбрасывает память и заменяет выбранный ZIP пустым корректным архивом. |

Парсер разделяет строку по пробелам, пропускает повторные пробелы и пустой ввод.
Кавычки и переменные окружения не обрабатываются. Ошибки отображаются в истории;
после ошибки можно продолжать ввод команд.
Если во время сессии была ошибка команды, чтения скрипта или загрузки VFS,
перед завершением выводится «Предупреждение: во время работы были ошибки.».
Это действует для `exit` из скрипта, ручного `exit` и закрытия окна кнопкой.
Без ошибок предупреждение не выводится.

## Историческая демонстрация этапа 1

Запустите `./run.sh`, проверьте имя VFS в заголовке, последовательно вводите:

```text
ls
ls /home /tmp
cd
cd /home
cd /home /tmp
unknown
exit extra
ls
exit
```

В коммите этапа 1 заглушки показывают имя и аргументы. Ошибочны `cd /home /tmp`, `unknown`
и `exit extra`; последующая `ls` выполняется. Последняя `exit` закрывает окно.
Дополнительно проверьте пустой ввод и несколько пробелов между аргументами.

Начиная с этапа 4 `ls` и `cd` работают с VFS; прежние пути могут давать ошибки.

## Настройки этапа 2

| Параметр | Значение |
| --- | --- |
| `--vfs PATH` | Путь к ZIP VFS. По умолчанию `default.zip`. |
| `--startup PATH` | Путь к стартовому UTF-8 скрипту. По умолчанию скрипта нет. |

Все настройки выводятся в окне и терминале при запуске. Неизвестные параметры,
повторы и пропущенные значения сообщаются в терминале; код завершения — 2.

```sh
./scripts/prepare-examples.sh
./run.sh --vfs build/examples/minimal.zip --startup examples/startup/stage2.txt
./scripts/demo-config-basic.sh
./scripts/demo-config-spaces.sh
./scripts/demo-config-errors.sh
./run.sh --startup examples/startup/exit.txt
```

Последовательно запускайте демонстрации и закрывайте каждое окно перед следующей.
`stage2.txt` исторически показывает заглушки и ошибки; строка после ошибки выполняется.
`exit.txt` показывает завершение скрипта по `exit` — последняя строка не выполняется.
При выполнении скрипта интерактивный ввод временно отключён.
Ошибка чтения скрипта отображается; после неё можно вводить команды вручную.
Пустые строки пропускаются. Комментарии в скриптах не поддерживаются.

## Виртуальная файловая система этапа 3

ZIP загружается напрямую в память, без распаковки или изменения исходного файла.
В памяти сохраняются каталоги и содержимое всех файлов в base64; при чтении
получаются исходные байты. Сохраняются пустые каталоги; промежуточные каталоги
восстанавливаются, даже если они не записаны отдельными элементами ZIP.
При запуске отображаются количество файлов и каталогов и дерево VFS.
Это диагностика загрузки; команда `ls` отдельно перечисляет выбранный каталог.

`vfs-init` не принимает аргументы. VFS по умолчанию определена как пустой корень.
Команда заменяет выбранный ZIP валидным пустым архивом и очищает VFS в памяти.
Если запись не удалась, выводится ошибка и прежняя VFS в памяти сохраняется.
Обычная загрузка не пишет на диск; физическая очистка — служебное исключение,
предусмотренное заданием. При отсутствующем неявном `default.zip` запуск использует
пустой корень в памяти; архив создаётся только по `vfs-init`.

Явно заданный отсутствующий или повреждённый ZIP, неверные пути внутри архива
и конфликты файлов с каталогами сообщаются в окне и терминале.
При ошибке загрузки стартовый скрипт не выполняется; окно можно закрыть по `exit`.
Пути внутри VFS абсолютные, от `/`; `.` и `..` в записях ZIP не допускаются.

Последовательно запускайте скрипты, закрывая окно перед следующим запуском.
Каждый основной VFS-скрипт создаёт примеры заново и передаёт оба параметра запуска.

| Пример | Содержание |
| --- | --- |
| `build/examples/minimal.zip` | Пустая VFS с корневым каталогом. |
| `build/examples/several.zip` | Два текстовых файла и двоичный файл. |
| `build/examples/deep.zip` | `/home/student/projects/readme.txt`, другие файлы и пустой каталог. |

`examples/startup/stage3.txt` демонстрирует все команды и их режимы, ошибки,
продолжение после ошибок, сброс ZIP и завершение по `exit`.

Демонстрационные VFS-скрипты используют `stage3-interactive.txt` с теми же

`demo-vfs-errors.sh` показывает отсутствующий и повреждённый ZIP.

## Основные команды этапа 4

Все пути относятся к VFS, а не к каталогам macOS. Начальный каталог — `/`.
Абсолютный путь начинается с `/`, относительный вычисляется от текущего каталога.
Поддерживаются `.` и `..`, повторные `/`; выйти выше виртуального корня нельзя.
Каждый промежуточный элемент должен существовать и быть каталогом. Ошибка
не меняет текущий каталог. `vfs-init` сбрасывает его в `/` и очищает историю `cd -`.

- `ls` и `ls путь` показывают непосредственных детей в порядке имён.
  Для файла показывается его имя; пустой каталог даёт пустой вывод.
  Можно передать несколько путей. `-a` включает скрытые имена, `.` и `..`;
  `-R` обходит каталоги рекурсивно; `-l` показывает тип (`d` или `-`),
  виртуального владельца, группу, размер файла в байтах и имя.
  На этапе 4 владельцы — `root:root`, размер каталогов — 0. Это упрощённый
  длинный формат без настоящих прав доступа и временных меток.
  `-h` вместе с `-l` выводит читаемый размер в степенях 1024: `1.0K`, `1.5K`, `1.0M`.
  Без `-l` флаг `-h` принимается, но не меняет список имён.
  Флаги можно объединять и передавать раздельно: `ls -lah /home`, `ls -l -h -a /home`,
  `ls -alhR /home`. После `--` идут только пути.
- `cd путь` меняет каталог без вывода. `cd` возвращает в виртуальный корень;
  `cd -` возвращает в предыдущий каталог и выводит его абсолютный путь.
  `cd -- путь` позволяет передать имя, начинающееся с `-`.
  Домашний каталог реальной ОС не используется.
- `echo` выводит текст без раскрытия переменных, снятия кавычек или escape-последовательностей.
  Все аргументы, включая `-n`, считаются текстом; пустой вызов даёт пустую строку.
  Повторные пробелы нормализуются парсером.
- `find` ищет от текущего каталога; `find путь...` — от заданных файлов или каталогов.
  Результат включает сам корень поиска и его потомков, включая скрытые имена.
  `-name` проверяет только имя по glob-шаблону (`*`, `?`, `[abc]`, `[!abc]`);
  `-type f` выбирает файлы, `-type d` — каталоги. Предикаты сочетаются через И.
  `-print` обозначает обычный вывод путей. Для `find /` вывод абсолютный,
  для `find .` — `.` и `./...`. Нет совпадений — пустой вывод.
  Шаблоны вводятся без кавычек, поскольку парсер варианта 11 их не обрабатывает.

Опции `ls` и `cd` указываются перед путями; пути `find` — перед предикатами.
Другие режимы UNIX-команд не реализованы: неизвестные флаги, предикаты,
несуществующие пути и неверные аргументы отображаются как ошибки.
Команды этапа 4 не изменяют ни память VFS, ни исходный ZIP, кроме текущего каталога `cd`.

## Дополнительная команда этапа 5

`chown` меняет виртуального владельца и/или группу файлов и каталогов в памяти.
Все элементы после загрузки ZIP имеют `root:root`. Метаданные не сохраняются
в ZIP, не меняют его физического владельца, содержимое файлов или права macOS.
При новой загрузке они снова равны `root:root`; `vfs-init` создаёт пустой корень
с этими же метаданными. При ошибке физического сброса память сохраняется.

Поддерживаемые режимы:

| Вызов | Изменение |
| --- | --- |
| `chown alice путь` | Только владелец; группа сохраняется. |
| `chown alice:staff путь` | Владелец и группа. |
| `chown :staff путь` | Только группа; владелец сохраняется. |
| `chown alice: путь` | Владелец `alice` и виртуальная группа `alice`. |
| `chown 1000:2000 путь` | Числовые виртуальные IDs владельца и группы. |
| `chown alice путь1 путь2` | Несколько файлов и/или каталогов. |
| `chown -R alice:staff каталог` | Сам каталог и все потомки, включая скрытые элементы. |
| `chown -R -- alice:staff путь...` | Конец опций; далее владелец и пути. |

Имена начинаются с латинской буквы или `_`, далее допускают буквы, цифры,
`_`, `.`, `-` и необязательный завершающий `$`. Числовой ID состоит из цифр.
Это виртуальные идентификаторы: существование такого пользователя в macOS
не проверяется. Форма `alice:` задаёт группу с именем владельца, поскольку
у VFS нет базы пользователей и их основных групп. Вызов `:staff` меняет только группу.

Пути бывают абсолютными и относительными, с `.` и `..`, как у других команд.
Без `-R` смена владельца каталога не затрагивает потомков. Опции идут перед владельцем.
Успешный `chown` не выводит текст; результат виден через `ls -l` или `ls -alR`.
Например, `chown alice:staff /root.txt` даёт `- alice staff 13 root.txt` в длинном выводе.
Несуществующие пути, неверный формат, пропущенные аргументы и неизвестные флаги
дают ошибку. Все пути проверяются до изменения метаданных: ошибочный вызов
с несколькими путями сохраняет прежних владельцев всех элементов.

## Соответствие заданию

Этапы 1–5 реализованы; этапы 4 и 5 имеют отдельные ветки и отдельные коммиты.
Каждый этап имеет отдельный коммит с Conventional/Scoped Commit сообщением.
Демонстрации и команды проверки приведены выше; ZIP создаются только при запуске

## Документация исходников

`CommandParser.parse` разбирает ввод, `Shell.execute` возвращает результат команды,
`TerminalPanel.append` добавляет вывод, `TerminalWindow.show` показывает окно,
`main` запускает приложение. Назначение остальных функций описано в KDoc.
`AppConfig.parse` проверяет параметры, `debugDescription` описывает настройки,
`StartupScript.run` исполняет стартовый скрипт и отображает диалог.
`ZipVfs.load` читает архив, `ZipVfs.reset` очищает его физическое представление,
`ZipTreeBuilder` проверяет записи и строит дерево, `VirtualFileSystem.paths/read/describe`
дают пути, исходные байты и диагностику дерева, `VfsSession.initialize` сбрасывает
сессию и навигацию. `ExampleArchives.create` генерирует демонстрационные ZIP.
`VfsNavigation.resolve/changeDirectory/reset` разрешают пути, меняют и сбрасывают
текущий каталог. `VirtualFileSystem.contains/isDirectory/children/subtree/size`
дают сведения о дереве в памяти. `CommandOptions.parse` проверяет короткие флаги
и `--`. `ListCommand.execute` перечисляет элементы, `FindCommand.execute` ищет их.
`GlobPattern.matches` сопоставляет шаблон с именем, включая виртуальный корень `/`.
`VirtualFileSystem.ownership/changeOwnership` читают и меняют метаданные,
`VfsOwnership` хранит владельца и группу, `ChownCommand.execute` проверяет вызов
и меняет выбранные элементы только в памяти.
Приватные функции документированы в KDoc рядом с реализацией.
